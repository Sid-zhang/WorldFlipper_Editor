# WF CN 内容编辑平台 1.0.0

> 作者：**随风** · 本工具仅供授权方内部使用 · 保留所有权利

一个**离线可用**的《世界弹射物语》国服内容编辑工具：改主数据、预览美术资源、打 CDN 补丁包，全程在你自己机器上完成。

## 二、首次使用（三步）

```powershell
# 1) 生成配置（把 config.example.json 复制成 config.json）
node server.js --init-config

# 2) 打开 config.json，把这几项改成你自己机器上的真实路径
#    cdnDir       补丁链目录（编辑器在这里产出补丁包）
#    baselineDir  基线 CDN 目录（游戏主数据，含 cn/ 分卷）
#    serverDir    你的服务端部署目录（可选；要用「发布」或「推送测试」时必填）
#    workspaceDir / workDir   编辑器状态与临时工作区
#    accountsFile 账号文件（多用户部署时由管理员维护）

# 3) 启动
node server.js
# 浏览器打开 http://127.0.0.1:4810/platform
```

> 没有 `config.json` 时程序会**明确报错并退出**，不会用默认值悄悄跑起来；缺哪个键、该填什么，报错里会写清楚。

**交付有两种形态**，按你的机器选：

| 包 | 适用 | 说明 |
|---|---|---|
| `wf-toolchain-1.0.0-with-node20-win-x64.zip` | **推荐**，解压即用 | **自带 Node 20.20.2**：解压后 `node\` 与 `wf-toolchain\` 平级，双击 `wf-toolchain\start-editor.bat` 即可，机器上不需要装 Node |
| `wf-toolchain-1.0.0.zip` | 已装 Node 20+ | 不含 Node，用系统 `node` 启动 |
| `wf-toolchain-1.0.0-update.zip` | 覆盖升级 | 只含代码，**不含配置与 Node**，覆盖解压到已有安装目录即可 |

## 三、多用户（部署在服务器上）

支持「一台服务器 + 多个使用者」：`accountsFile` 指向账号文件，未通过校验的请求一律 401。

- 账号由管理员在**服务器本机**生成（`node scripts/make-account.cjs`）；
- **不支持自助注册**（结构性设计，不是没做）；
- 默认只绑 `127.0.0.1`；要让其他人直连，在 `config.json` 里显式写 `"host": "0.0.0.0"`。

## 四、「推送测试」需要你的服务端支持（可自行实现）

这是一个**默认隐藏**的可选功能：把改动直接推给「本机测试服 + 测试设备」，不新增版本号、不写补丁链、客户端零下载。

启用条件（`config.json` 的 `devPush` 段）：`adb`（adb.exe 路径）、`devices`（设备列表，如 `127.0.0.1:16384`）、`serverDir`（或全局 `serverDir`）。
设备需已 root、已安装客户端。服务端最好支持下面 6 条；缺第 2/3 条也能用，会退化为「重启后生效」：

1. 支持 `CDN_DIR` 环境变量，把静态 CDN 根指到任意目录；
2. 启动时（或请求时）对 `<CDN_DIR>/patches/*` 做内容快照/激活；
3. 在 stdout 打一行 JSON：
   `[content-hot-sync] {"status":"synchronized","targetVersion":"x.y.z","currentVersion":"a.b.c","reason":"…","releaseDigest":"sha256:…"}`
4. 同步失败时打印 `CONTENT_SYNC_FAILED`；
5. HTTP 可达（编辑器探活用）；
6. 可用 `node <serverDir>/out/cn-server.js` 启动，端口可配。

## 五、目录说明

```
wf-toolchain/
├── server.js            服务入口（HTTP，默认 4810）
├── config.example.json  配置示例（首次使用会被复制成 config.json）
├── version.json         版本载体（含作者署名）
├── BUILD.json           构建记录（版本 / 构建时间 / 打包工具版本）
├── lib/                 后端
├── public/              前端页面
├── plugins/             各管线的页签声明
└── assets/              随包资源
```

`workspace/`（编辑器状态）、`work/`（临时工作区）、日志文件都在运行时生成，不属于交付内容。

## 六、常见问题

| 现象 | 原因与处置 |
|---|---|
| 启动即退出，提示找不到 `config.json` | 按第二节第 1 步生成 |
| 打开页面 401 | 账号鉴权未通过：检查 `accountsFile` 与凭据 |
| 某个管线点不开 | 该管线在本版本未提供（页签标注「待开发」，设计如此） |
| 「推送测试」整块看不见 | `config.devPush` 不完整（刻意的默认隐藏） |
| 改了 `lib/**` 页面没变化 | 需要**重启进程**（没有热重载）；只改 `public/**` 刷新即可 |
